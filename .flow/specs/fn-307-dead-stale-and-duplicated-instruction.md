# Dead, stale and duplicated instruction text (audit 2026-10 wave 1)

## Goal & Context
<!-- Goal & Context: 20% [paraphrase], 80% [inferred] -->

The monthly maintenance pass asked to "go through every single skill and path to see what should be trimmed without regressing, efficiency gains". Seven read-only auditors covered every shipped skill, agent, reference, command shim, rule and template at 9.4.0 and measured what each path reads. The default fast paths (single-task work, impl-review through a CLI backend, make-pr, land) are already lean. The waste sits in text no agent can act on: pointers to sections that moved, rules contradicted by the code or by another file on the same path, history and outside-source names that shipped skills must not carry, files nothing reads, and rules restated across files that always load together.

Every item below was then re-checked line by line against the files by the host (not by subagents), on Gordon's request for full confidence. Items that failed the check were dropped, two auditor proposals were reversed, and six items that need a decision or a measurement moved to fn-260. This wave keeps only what survived: no behaviour change, every rule an agent follows today still stated once on the path where it acts.

## Architecture & Data Models

No new components. Every change edits an existing skill, reference, agent, command shim, rule or the Codex mirror generator. Canonical files are edited and the Codex mirror is regenerated, never hand-edited. Exact locations are re-derived by grep at build time, since line numbers drift; the maintainer's audit record holds the reviewed coordinates.

## Edge Cases & Constraints

- A duplicate is removed only when the kept copy is read on every path that read the removed one; when one copy sits in a gated reference and the other on the common path, the common-path copy stays. [inferred]
- No text moves to a file the agent might not read on that path. [inferred]
- Lines that block a known failure (a "has broken this" line, an explicit prohibition) stay unless the failure is impossible in code. [inferred]
- A shell function or variable defined in more than one fence is not a duplicate: shell state does not survive between tool calls, so each fence keeps its own definition. [inferred]
- Tests assert behaviour or a minimal token (G2). Fences and tokens tests execute or pin stay intact; a trim that breaks a pin is dropped, not forced. [inferred]
- Removed or corrected prose leaves no dangling reference elsewhere (grep before delete). [inferred]
- Verification for the whole wave, beyond each criterion's own check: the repository's full unit suite and Ruff pass once at the end; the Codex mirror is regenerated and its check passes; the shipped-link test passes over every changed file; the flowctl-surface test confirms every verb the changed prose names exists; each touched skill's conduct checklist is walked once against the diff and the result is noted in the PR; and four host smoke runs from the branch's plugin, each against a disposable fixture, show the touched paths still reach their terminals: impl-review on the host backend with `--validate` (verdict and validator receipt keys written), plan-review on the host backend (receipt written at its path), audit in `mode:autofix` over fixture memory (changes go through `memory apply`, no `git rm`, no hand-edited YAML), and resolve-pr `--dry-run` on a real pull request (plan printed, nothing changed). A smoke that fails blocks the wave. [inferred]
